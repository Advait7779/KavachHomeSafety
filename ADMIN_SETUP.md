# Admin panel setup

The admin UI is at `/admin`. The backend requires PostgreSQL. Copy `.env.example` to `.env` and set a strong database password, admin email, and admin password (at least 6 characters, at most 72 UTF-8 bytes). The first API start creates the initial admin account only if no account exists. Later changes to `ADMIN_PASSWORD` do not reset an existing account.

## Docker Compose

Run `docker compose -f compose.yaml -f compose.local.yaml up --build -d` for a local Docker deployment at `http://127.0.0.1:4004`. The production Compose file does not publish a host port. In Coolify, select the repository's Compose build strategy, use **only** `compose.yaml`, and attach the HTTPS website domain to the **web** service at internal port **4004**. The **api** service listens on internal port **6002**; an optional API subdomain should target that service and port. Set `POSTGRES_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `PUBLIC_SITE_URL` as Coolify environment variables. Use a unique production password for PostgreSQL and a different strong admin password. The first API start fails if no admin exists and the admin credentials are missing or invalid. An existing admin password is not changed by updating the environment variable; change it in the admin Settings page.

The API, PostgreSQL database, and uploaded images run as separate services. The database and uploads use persistent named volumes. Both web and API have health checks; `/api/health` checks the database. Nginx serves assets and forwards public HTML, `/api`, and `/uploads` to the API service. The canonical hostname defaults to `https://kavachinvisiblesaftygrill.com`; override `PUBLIC_SITE_URL` only if that changes. Localhost previews remain accessible without redirecting to the production hostname.

Before deployment, commit and push the admin, server, shared, Compose, and configuration files. A new Compose PostgreSQL volume starts empty. If the local `kavach` database already contains leads, bills, or edits that must be retained, transfer it with a PostgreSQL dump and restore before opening the new site to visitors. Back up both the database and uploads to an off-server destination on a schedule, and test restoring both to a disposable stack. A persistent volume alone is not a backup.

After deployment, confirm the domain uses HTTPS, `/api/health` returns `{"status":"ok"}`, `/admin` loads, an unauthenticated `/api/admin/leads` request returns 401, admin login works, an enquiry appears under Leads, image upload and PDF preview work, and `/robots.txt` and `/sitemap.xml` use the final domain. Check the real client IP and rate-limit headers through Coolify's proxy, and check logs for CSP violations or failed health checks. Do not expose the API, database, or Nginx host port directly to the internet.

## Local development

Start PostgreSQL and put `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD` in an ignored `.env.local` file. `npm run dev:api`, `npm run start:api`, and `npm start` load that file automatically; process environment variables take precedence. Run `npm install`, `npm run dev:api`, and `npm run dev` in separate terminals. Vite forwards `/api` and `/uploads` to port 6002. For a single server with server-rendered public HTML, run `npm run build` followed by `npm start` and open `http://127.0.0.1:6002/`. These commands also work from the `server` folder because npm finds the project root package.

The enquiry form saves a lead before displaying a WhatsApp follow-up link. Admin site edits stay in a draft until **Publish changes** is clicked. **Estimates & Bills** creates either document type in a compact popup over the document list. The popup has Customize and Preview tabs, editable item rows, a total and save controls in Customize, and expandable Kavach company details. Preview uses the current fields without saving and includes Open PDF and Download PDF links. New documents calculate no tax, even if an older client submits a tax rate. New estimates use Kavach branding in a white, orange, and dark A4 layout based on the supplied reference. Company, customer, item, amount-in-words override, description, and terms fields are editable while the document is a draft. Estimates are limited to one page; an overlong estimate returns a clear error so it can be shortened. Existing bills keep their earlier PDF format. Issued documents are locked, and the dashboard's outstanding-bill totals count invoices only.

The Estimates and Bills lists show the saved customer contact number and a PDF download action. Once a draft is complete and saved, click the download icon to save its PDF, then send the file manually. Incomplete drafts cannot be downloaded. The separate public PDF-link endpoint remains available for link-based sharing; its links expire after 30 days and local development links cannot be opened by customers on other devices.

Estimate terms stay on estimates. Bills show a bold "Thank you for choosing Kavach." footer; optional bill notes appear above it. Bills saved with the earlier estimate terms display the thank-you footer instead.

Production HTML uses a Content Security Policy. Admin uploads are limited to 5 MB, 30 uploads per day per client IP, and JPG/PNG/WebP file signatures. Admin sessions expire after 12 hours or 2 hours of inactivity; changing the password revokes other sessions. Publishing and rolling back site content and changing lead status or password write basic audit events to the database. MFA and a full audit viewer remain future security enhancements.

`npm run test:pdf` checks invoice PDF pagination without touching PostgreSQL. `npm run test:api` is destructive and must only run against a disposable database whose name ends `_test` or `_smoke`, with `TEST_DATABASE_URL`, `TEST_DATABASE_CONFIRM=disposable`, and test admin credentials set. It resets that database, publishes test content, and changes the test password. Never point it at production or the working local database.

## SEO launch checks

The public pages are server-rendered in the production setup. Visit `/robots.txt` and `/sitemap.xml` on the final domain, check that `/`, `/services`, `/gallery`, and `/contact` have distinct titles and self-referencing canonicals, and submit the sitemap in Google Search Console. Confirm the published business name, address, and phone before relying on the LocalBusiness markup. The admin SEO tab edits search and social metadata without changing the public page layout.
